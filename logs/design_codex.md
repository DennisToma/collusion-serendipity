The pilots can support narrow exploratory verdicts, but three points need correction or clarification before outcomes. No files were edited.

1. **S01 can declare HIT without any predictive improvement.** Its primary contrast compares the assigned pair’s prediction gain with other pairs’ gains. Suppose adding digits increases error by 0.1 for the assigned pair and by 0.5 for other pairs. The primary contrast is then **+0.4**, potentially satisfying HIT in both families, although digits worsen every prediction. That supports “relatively less harmful augmentation,” not useful last-digit prediction.

   **Fix:** Require positive absolute held-out improvement for the assigned pair in both families, alongside the existing positive assigned-minus-others contrast. Freeze whether the absolute-benefit requirement concerns the point estimate or an uncertainty bound. Otherwise, explicitly define HIT as relative performance only. ([DESIGN.md:16](/home/factory/collusion/collusion-serendipity/DESIGN.md:16))

2. **S01’s bootstrap must specify whether it includes model-fitting uncertainty.** Holding out whole runs prevents within-run leakage, but cross-validation scores are still dependent: different held-out games are evaluated using overlapping training sets. Simply bootstrapping cached game scores treats those fitted predictors as fixed and does not reproduce uncertainty from learning the predictors. Consequently, a positive “95% interval” need not support the advertised robust out-of-run signal.

   **Fix:** Freeze a game-level bootstrap that reruns training-only preprocessing and both regressions within each replicate. Keep all copies of an original game in the same fold to prevent bootstrap duplicates leaking across training and evaluation. Resample at any higher shared assignment or simulation-block level if games are dependent there. An alternative is a frozen training set and independent evaluation games, with inference explicitly conditional on the fitted models. ([DESIGN.md:19](/home/factory/collusion/collusion-serendipity/DESIGN.md:19))

3. **S02’s execution schedule does not establish a causal opportunity effect.** Randomizing the participating pair does not randomize channel availability across execution slots. Deterministically interleaving arms can leave channel status associated with API time, batching, or backend conditions. Without coupled model randomness, each arm also receives an independent stochastic trajectory; shared seed labels do not remove this variation. The design acknowledges drift, but its “opportunity effect” wording still requires an identification argument.

   **Fix:** Within each seed block, randomly assign channel/no-channel to two prespecified execution slots before calls begin. Keep the pair, initialization, and non-treatment prompts identical; run blocks close together and record execution timing/backend. Then analyze the five randomized block differences. Independent model sampling is acceptable under this assignment.

   The five-seed bootstrap remains a separate limitation: its nominal 95% bounds should not be treated as calibrated evidence that an effect exists or that a reduction of one unit is excluded. If keeping this budget, retain HIT/DUD only as explicitly heuristic prioritization labels and report all five block differences. Stronger evidential verdicts require more independent blocks and a frozen inference procedure. ([DESIGN.md:35](/home/factory/collusion/collusion-serendipity/DESIGN.md:35))
